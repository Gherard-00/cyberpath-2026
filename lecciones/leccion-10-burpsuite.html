Fase 2 — Pentesting Fundamental

Burp Suite — Pentesting de aplicaciones web

Burp Suite es la herramienta número uno para pentesting de aplicaciones web. Funciona como un proxy HTTP que intercepta todo el tráfico entre tu navegador y el servidor, permitiéndote ver, modificar y repetir peticiones. En esta lección aprenderás a configurarlo y usar sus módulos principales: Proxy, Repeater, Intruder y Decoder.

1. ¿Qué es Burp Suite y cómo funciona?

Burp Suite actúa como un hombre en el medio (MitM) entre tu navegador y el servidor web. Todo el tráfico HTTP/HTTPS pasa por Burp, donde puedes inspeccionarlo, modificarlo y reenviarlo. 

    Navegador ──▶ BURP SUITE (Proxy) ──▶ Servidor Web
        ◀──────── (intercepta y modifica) ◀──────

Burp viene pre-instalado en Kali Linux. Existe la versión Community (gratuita) y Professional (de pago con más funciones).

2. Configuración inicial y proxy

Configurar Burp Suite
# 1. Abrir Burp Suite
$ burpsuite &

# 2. Configurar el proxy del navegador
# Firefox → Configuración → Proxy de red → Configuración manual:
#   HTTP Proxy: 127.0.0.1   Puerto: 8080
#   Marcar: "Usar este proxy para todos los protocolos"

# 3. Instalar el certificado CA de Burp (para interceptar HTTPS)
# Navega a: http://burp  → Download CA Certificate
# Firefox: Configuración → Certificados → Importar → selecciona el .der

# TIP: Usa la extensión FoxyProxy en Firefox para cambiar fácilmente
# entre proxy ON (Burp) y proxy OFF (directo)

3. Proxy: interceptar y modificar peticiones

Con Intercept activado, cada petición HTTP que hagas se pausa en Burp, mostrándote todo su contenido. Puedes leerla, modificarla y reenviarla.

Ejemplo: modificar una petición
# Petición interceptada (login de DVWA):
POST /login.php HTTP/1.1
Host: 10.0.2.15
Content-Type: application/x-www-form-urlencoded

username=admin&password=password&Login=Login

# Puedes modificar cualquier campo antes de enviar:
# - Cambiar el username o password
# - Agregar headers
# - Modificar cookies
# - Inyectar payloads de SQLi o XSS

# Botones clave:
# Forward  → Enviar la petición (modificada o no)
# Drop     → Descartar la petición (no se envía)
# Send to Repeater → Enviar a Repeater para probar variaciones

4. Repeater: probar manualmente

Repeater te permite enviar una petición una y otra vez, modificándola cada vez, y ver la respuesta del servidor al instante. Es perfecto para probar payloads de SQLi, XSS, IDOR, etc.

Usando Repeater para probar IDOR
# 1. Intercepta una petición con Proxy
# 2. Click derecho → "Send to Repeater"
# 3. En Repeater, modifica el ID y haz clic en "Send"

# Petición original:
GET /api/user/profile?id=1001 HTTP/1.1

# Prueba 1: cambiar a otro usuario
GET /api/user/profile?id=1002 HTTP/1.1
# → ¿Ves datos de otro usuario? = IDOR confirmado

# Prueba 2: probar el admin
GET /api/user/profile?id=1 HTTP/1.1

# Prueba 3: inyección SQL
GET /api/user/profile?id=1 OR 1=1 HTTP/1.1

5. Intruder: ataques automatizados

Intruder automatiza ataques enviando muchas peticiones con diferentes payloads. Ideal para fuerza bruta, fuzzing y enumeración.

ModoDescripciónUso típico
SniperUn payload a la vez en una posición.Probar una lista de passwords en un campo.
Battering RamEl mismo payload en todas las posiciones.Probar una palabra en usuario Y contraseña.
PitchforkPayload diferente por posición, en paralelo.Lista de usuarios + lista de passwords alineadas.
Cluster BombTodas las combinaciones de payloads.Fuerza bruta: todos los usuarios × todas las passwords.

6. Decoder y Comparer

Decoder codifica/decodifica texto en varios formatos (Base64, URL encoding, HTML encoding, hex). Comparer compara dos respuestas para encontrar diferencias sutiles.

Decoder — Ejemplos
# Base64 decode:
YWRtaW46cGFzc3dvcmQ=  →  admin:password

# URL decode:
%27%20OR%201%3D1%20--  →  ' OR 1=1 --

# HTML decode:
&lt;script&gt;alert(1)&lt;/script&gt;  →  <script>alert(1)</script>

7. Práctica: hackear DVWA con Burp

Ejercicios
# 1. Configura Burp como proxy de tu navegador
# 2. Navega a DVWA e intercepta el login
# 3. Envía la petición de login a Repeater
# 4. Prueba SQLi en el campo de usuario: admin' OR '1'='1' --
# 5. Usa Intruder (Sniper) para fuerza bruta del login:
#    - Posición: el campo password
#    - Payload: lista de contraseñas comunes
#    - Observa las diferencias en la longitud de respuesta
# 6. Usa Repeater para probar XSS reflected en la página de búsqueda
