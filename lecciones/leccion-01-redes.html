Redes y TCP/IP — Cómo se comunican las computadoras

Antes de intentar hackear cualquier sistema, necesitas entender cómo viajan los datos por la red. Cada vez que abres una página web, envías un correo o haces un ping, ocurren cosas complejas por debajo que necesitas dominar. En esta lección vas a aprender cómo funciona Internet desde adentro: qué es una dirección IP, qué son los puertos, cómo se establece una conexión TCP, qué hace el DNS y mucho más. Todo explicado de forma clara con ejemplos y analogías.

1. ¿Qué es una red de computadoras?

Una red de computadoras es simplemente un grupo de dispositivos (computadoras, teléfonos, servidores, impresoras) que están conectados entre sí para compartir información. Cuando tú accedes a Google, tu computadora envía un mensaje a través de la red hasta llegar a un servidor de Google, que te responde con la página web.

Analogía: La red es como el sistema postal

Imagina que quieres enviar una carta a un amigo. Necesitas: su dirección (la dirección IP), un sobre (el paquete de datos), un cartero y oficinas postales (los routers y switches), y un sistema para saber qué ruta tomar (los protocolos de enrutamiento). La red funciona exactamente igual, pero a la velocidad de la luz.

Tipos de redes

Las redes se clasifican por su tamaño:

  • LAN (Local Area Network): Red local — tu casa o una oficina. Todos los dispositivos están en el mismo lugar físico, conectados al mismo router.
  • WAN (Wide Area Network): Red de área amplia — Internet es la WAN más grande del mundo. Conecta LANs que están en diferentes ciudades o países.
  • WLAN: Red local inalámbrica — tu WiFi de casa es una WLAN.

¿Qué componentes forman una red?

Componente Qué hace Analogía
Router Dirige los paquetes de datos entre diferentes redes. Tu router en casa conecta tu LAN con Internet. La oficina postal que decide por qué ruta enviar tu carta
Switch Conecta dispositivos dentro de la misma red local y envía datos solo al destinatario correcto. El cartero que sabe a qué buzón exacto entregar la carta
Firewall Filtra el tráfico: decide qué datos pueden pasar y cuáles se bloquean según reglas de seguridad. El guardia de seguridad que revisa quién entra y quién no
Servidor Computadora que ofrece servicios: web, correo, archivos, DNS, etc. La empresa que procesa tu pedido y te envía lo que pediste

2. El modelo OSI y TCP/IP: las capas de la red

Para que dos computadoras se comuniquen, los datos pasan por varias capas, cada una con una función específica. Existen dos modelos que explican esto: el modelo OSI (teórico, 7 capas) y el modelo TCP/IP (práctico, 4 capas, el que realmente usa Internet).

Analogía: Las capas son como envolver un paquete

Imagina que quieres enviar un regalo. Primero lo envuelves en papel (capa de aplicación: los datos), luego lo metes en una caja (capa de transporte: TCP/UDP), luego le pones la dirección de envío (capa de red: IP), y finalmente lo entregas al servicio de mensajería (capa de acceso: la red física). Cuando llega al destinatario, se "desenvuelve" en orden inverso.

El modelo TCP/IP (el que importa en la práctica)

Internet funciona con el modelo TCP/IP, que tiene 4 capas:

Capa Nombre ¿Qué hace? Protocolos principales Ejemplo cotidiano
4 Aplicación Es lo que el usuario ve e interactúa. Aquí vive tu navegador web, tu cliente de email, etc. HTTP, HTTPS, DNS, FTP, SSH, SMTP Abrir google.com en el navegador
3 Transporte Garantiza que los datos lleguen completos y en orden (TCP) o los envía rápido sin garantía (UDP). TCP, UDP TCP: cargar una web. UDP: ver un stream de video en vivo
2 Red (Internet) Se encarga de las direcciones IP y de decidir la ruta que siguen los paquetes. IP, ICMP, ARP El GPS que decide por qué carreteras va tu paquete
1 Acceso a Red El medio físico: cables, WiFi, tarjetas de red. Maneja las direcciones MAC. Ethernet, WiFi (802.11) El cable de red o la señal WiFi que conecta tu computadora

¿Por qué importa esto para la ciberseguridad?

Cada capa tiene sus propias vulnerabilidades. Un ataque puede ocurrir en la capa de aplicación (inyección SQL en una web), en la capa de transporte (un ataque SYN flood), en la capa de red (spoofing de IP) o en la capa física (interceptar tráfico WiFi). Para defender o atacar un sistema, necesitas entender qué pasa en cada capa.

3. Direcciones IP: la dirección de cada computadora

Cada dispositivo conectado a una red necesita una dirección IP (Internet Protocol) para poder recibir y enviar datos. Es como la dirección de tu casa: sin ella, nadie puede encontrarte.

IPv4: la versión que usamos hoy

Una dirección IPv4 se compone de 4 números separados por puntos, donde cada número va de 0 a 255. Cada número se representa internamente con 8 bits (un byte), lo que da un total de 32 bits.

Ejemplo de dirección IPv4 
192.168.1.100

Desglose:
  192     .  168     .  1       .  100
  ├─8 bits─┤ ├─8 bits─┤ ├─8 bits─┤ ├─8 bits─┤
  = 11000000.10101000.00000001.01100100  (en binario)
  
  Total: 32 bits = 4 bytes

Cada sección entre puntos se llama octeto porque tiene 8 bits. Con 32 bits se pueden crear 2^32 = 4,294,967,296 direcciones únicas (por eso se están agotando y existe IPv6).

Tipos de direcciones IP

No todas las IPs se usan para Internet. Hay dos tipos importantes:

Tipo Rango Uso
IP privada 10.0.0.0 – 10.255.255.255
172.16.0.0 – 172.31.255.255
192.168.0.0 – 192.168.255.255		 Se usan dentro de tu red local (tu casa, oficina). No son accesibles desde Internet. Tu router traduce estas a una IP pública usando NAT.
IP pública Cualquier otra (ej. 8.8.8.8, 142.250.80.46) Son únicas en todo Internet. Es la dirección que el mundo ve de tu red.
Loopback 127.0.0.1 (localhost) Tu propia máquina. Cuando escribes 127.0.0.1 te estás conectando a ti mismo. Útil para probar servicios localmente.

¿Qué es NAT?

NAT (Network Address Translation) es lo que hace tu router para que todos los dispositivos de tu casa compartan una sola IP pública. Tu computadora tiene IP privada 192.168.1.100, pero cuando sale a Internet, el router la traduce a su IP pública (ej. 86.34.22.156). Cuando la respuesta vuelve, el router sabe a qué dispositivo interno reenviarla.

4. Subnetting: dividir redes en segmentos

Subnetting es dividir una red grande en redes más pequeñas (subredes). ¿Por qué? Por seguridad y organización. En una empresa, puedes tener una subred para contabilidad, otra para ventas, otra para servidores — así, si un atacante compromete una subred, no tiene acceso automático a las demás.

La máscara de subred

La máscara de subred define qué parte de una IP identifica la red y qué parte identifica al host (dispositivo). Se escribe en notación CIDR con una barra y un número (ej. /24).

Entendiendo la máscara /24 
IP:       192.168.1.100 /24
Máscara:  255.255.255.0

En binario:
  IP:       11000000.10101000.00000001.01100100
  Máscara:  11111111.11111111.11111111.00000000
            ├──── parte de RED (24 bits) ────┤├ HOST ┤

  Los primeros 24 bits (los "1") identifican la RED: 192.168.1.0
  Los últimos 8 bits (los "0") identifican al HOST: .100

Red:      192.168.1.0     (dirección de la red — no se asigna)
Broadcast: 192.168.1.255  (envía a todos — no se asigna)
Rango utilizable: 192.168.1.1 hasta 192.168.1.254 (254 hosts)

Fórmula para calcular hosts: Hosts = 2^(32 - n) - 2 donde n es la máscara CIDR.

Para /24: 2^(32-24) - 2 = 2^8 - 2 = 256 - 2 = 254 hosts

Para /16: 2^(32-16) - 2 = 2^16 - 2 = 65,534 hosts

Se restan 2 porque la primera dirección es la dirección de red y la última es el broadcast.

5. Puertos: las puertas de cada servicio

Una dirección IP te lleva a una computadora, pero una computadora puede tener muchos servicios corriendo al mismo tiempo (web, correo, SSH, base de datos). ¿Cómo sabe la computadora a qué servicio va cada paquete? Con los puertos.

Analogía: Un edificio con departamentos

La dirección IP es la dirección del edificio (ej. "Av. Principal #456"). El puerto es el número de departamento (ej. "Depto. 80"). Si quieres visitar al servicio web, vas al departamento 80. Si quieres SSH, vas al 22. El edificio es la misma computadora, pero cada servicio "vive" en un puerto diferente.

Los puertos van del 0 al 65,535 (16 bits). Cada servicio usa un puerto estándar asignado:

Puerto Protocolo Qué hace ¿Por qué importa en pentesting?
21FTPTransferencia de archivosA menudo permite login anónimo o tiene credenciales débiles
22SSHAcceso remoto seguro (terminal)Objetivo principal para fuerza bruta de contraseñas
23TelnetAcceso remoto SIN cifrarTodo viaja en texto plano — se pueden capturar credenciales
25SMTPEnvío de correo electrónicoSe puede usar para enumerar usuarios válidos
53DNSResolución de nombres de dominioTransferencias de zona pueden revelar toda la infraestructura
80HTTPPáginas web sin cifrarVulnerabilidades web (SQLi, XSS, IDOR)
443HTTPSPáginas web con cifrado TLSMismo que HTTP pero con cifrado — igual tiene vulnerabilidades
445SMBCompartir archivos en WindowsEternalBlue, acceso a recursos compartidos sin autenticación
3306MySQLBase de datos MySQLSi está expuesto, se puede intentar acceso con credenciales por defecto
3389RDPEscritorio remoto de WindowsFuerza bruta, BlueKeep

¿Por qué es importante conocer los puertos?

Cuando haces un escaneo de puertos con Nmap (lo aprenderás en la Lección 8), estás buscando qué "puertas" están abiertas en un servidor. Cada puerto abierto es un posible vector de ataque. Por ejemplo, si encuentras el puerto 21 (FTP) abierto, puedes intentar conectarte con usuario anonymous. Si encuentras el 445 (SMB), puedes buscar vulnerabilidades como EternalBlue.

6. TCP vs UDP: dos formas de enviar datos

En la capa de transporte, hay dos protocolos principales para enviar datos: TCP y UDP. La diferencia clave es que TCP garantiza que los datos lleguen completos y en orden, mientras que UDP no garantiza nada pero es más rápido.

TCP (Transmission Control Protocol) — El protocolo confiable

TCP funciona como enviar una carta certificada: antes de enviar datos, las dos computadoras deben "ponerse de acuerdo" mediante un proceso llamado Three-Way Handshake (acuerdo de tres vías). Esto es FUNDAMENTAL entenderlo porque es la base de muchos ataques y escaneos.

El Three-Way Handshake explicado paso a paso

    TU COMPUTADORA                          SERVIDOR
          |                                     |
          |──── 1. SYN ────────────────────────▶|  "¡Hola! Quiero conectarme"
          |                                     |
          |◀─── 2. SYN-ACK ────────────────────|  "¡Hola! OK, acepto. ¿Listo?"
          |                                     |
          |──── 3. ACK ────────────────────────▶|  "¡Sí, listo! Empecemos"
          |                                     |
          |◀════ CONEXIÓN ESTABLECIDA ═════════▶|
          |                                     |
          |──── Datos ─────────────────────────▶|  Ahora sí se envían los datos
          |◀─── Datos ─────────────────────────|

El Three-Way Handshake de TCP: SYN → SYN-ACK → ACK

Explicado en detalle:

  1. SYN (Synchronize): Tu computadora envía un paquete con la bandera SYN activada diciendo "quiero conectarme contigo al puerto 80".
  2. SYN-ACK: Si el puerto está abierto, el servidor responde con SYN-ACK: "OK, acepto la conexión, estoy escuchando".
  3. ACK (Acknowledge): Tu computadora confirma: "Perfecto, vamos a comunicarnos". La conexión queda establecida.

⚠️ ¿Y si el puerto está cerrado?

Si el puerto está cerrado, el servidor responde con un paquete RST (Reset) en lugar de SYN-ACK, que significa "No hay nada escuchando aquí, vete". Si hay un firewall bloqueando, simplemente no responde nada (el paquete se pierde en el vacío). Esto es exactamente lo que Nmap analiza para determinar si un puerto está abierto, cerrado o filtrado.

UDP (User Datagram Protocol) — El protocolo rápido

UDP no hace handshake. Simplemente envía los datos y espera que lleguen. Es como gritar un mensaje por la ventana: puede que lo escuchen, puede que no, pero es rápido. Se usa para cosas donde la velocidad importa más que la fiabilidad: videollamadas, streaming, juegos online, DNS.

Característica TCP UDP
ConexiónRequiere handshake previoSin conexión, envía directo
FiabilidadGarantiza entrega y ordenNo garantiza nada
VelocidadMás lento (por las verificaciones)Más rápido
Uso típicoWeb (HTTP), email, SSH, FTPDNS, video, juegos, VoIP
En pentestingEscaneo SYN, ataques SYN FloodEscaneos UDP (más lentos y difíciles)

7. DNS: traducir nombres a direcciones IP

Los humanos no recordamos números fácilmente. Es más fácil recordar google.com que 142.250.80.46. El DNS (Domain Name System) es el servicio que traduce los nombres de dominio a direcciones IP. Es como la guía telefónica de Internet.

¿Cómo funciona una consulta DNS?

Cuando escribes google.com en tu navegador, esto es lo que pasa:

  1. Tu computadora revisa su caché local: "¿Ya resolví este nombre antes?" Si sí, usa la IP guardada.
  2. Si no, pregunta al servidor DNS configurado (generalmente el de tu proveedor de Internet o 8.8.8.8 de Google).
  3. Si ese servidor tampoco lo sabe, pregunta a los servidores raíz (los "jefes" del DNS mundial).
  4. Los servidores raíz redirigen al servidor del dominio .com, que a su vez redirige al servidor de google.com.
  5. Finalmente, se obtiene la IP 142.250.80.46 y se devuelve a tu computadora.
  6. Tu navegador puede ahora conectarse a esa IP.
Practica: resolver un dominio con nslookup 
$ nslookup google.com
Server:         8.8.8.8
Address:        8.8.8.8#53

Non-authoritative answer:
Name:   google.com
Address: 142.250.80.46

El comando nslookup le pregunta al servidor DNS cuál es la IP de google.com. La respuesta "Non-authoritative" significa que vino de un caché, no del servidor oficial de Google.

También puedes usar dig google.com en Linux para una respuesta más detallada.

¿Por qué DNS importa en ciberseguridad?

El DNS es un objetivo frecuente de ataques: DNS Spoofing (envenenar el DNS para redirigir a sitios falsos), DNS Tunneling (esconder datos dentro de consultas DNS para exfiltrar información), y transferencias de zona (obtener una lista completa de todos los subdominios de un objetivo). También es una herramienta de reconocimiento: mediante DNS puedes descubrir subdominios, servidores de correo y más.

8. HTTP/HTTPS: cómo funciona la web

HTTP (HyperText Transfer Protocol) es el protocolo que usa tu navegador para comunicarse con los servidores web. Cada vez que abres una página, tu navegador envía una petición HTTP y el servidor responde con el contenido (HTML, CSS, imágenes, etc.).

Anatomía de una petición HTTP

Cuando visitas http://ejemplo.com/pagina, tu navegador envía algo como esto:

Petición HTTP — lo que envía tu navegador 
GET /pagina HTTP/1.1
Host: ejemplo.com
User-Agent: Mozilla/5.0 (X11; Linux x86_64)
Accept: text/html
Cookie: session=abc123

GET — El método: "quiero OBTENER este recurso". Otros métodos: POST (enviar datos), PUT (actualizar), DELETE (borrar).

/pagina — La ruta del recurso que se solicita.

Host — A qué servidor va dirigida la petición.

Cookie — Tu sesión activa. Si un atacante roba esta cookie, puede suplantar tu identidad.

La respuesta del servidor

Respuesta HTTP — lo que devuelve el servidor 
HTTP/1.1 200 OK
Content-Type: text/html
Content-Length: 1234

<html>
  <body>Bienvenido a la página</body>
</html>

200 OK — Código de estado: todo salió bien. Otros códigos importantes:

• 301 / 302 — Redirección (el recurso se movió)

• 403 — Prohibido (no tienes permiso)

• 404 — No encontrado

• 500 — Error interno del servidor (posible vulnerabilidad)

HTTPS = HTTP + TLS

HTTPS es HTTP pero con una capa de cifrado TLS (Transport Layer Security). Antes de intercambiar datos, el servidor presenta un certificado digital que demuestra su identidad, y ambas partes negocian una clave de cifrado. A partir de ahí, todo el tráfico va cifrado — nadie que intercepte la comunicación puede leer el contenido.

9. El flujo completo: qué pasa cuando visitas una web

Ahora juntemos todo. Cuando escribes https://seguridad.local en tu navegador, esto es lo que pasa paso a paso:

PasoProtocolo¿Qué pasa?
1. Resolución DNS DNS (puerto 53) Tu computadora pregunta al servidor DNS: "¿Cuál es la IP de seguridad.local?" y obtiene, por ejemplo, 10.0.2.15.
2. Conexión TCP TCP (puerto 443) Se ejecuta el Three-Way Handshake (SYN → SYN-ACK → ACK) para establecer la conexión con el servidor en el puerto 443 (HTTPS).
3. Cifrado TLS TLS Se negocian algoritmos de cifrado, el servidor presenta su certificado digital y se intercambian claves para asegurar la comunicación.
4. Petición HTTP HTTP Tu navegador envía GET /index.html HTTP/1.1 y el servidor responde con 200 OK y el contenido HTML de la página.
5. Enrutamiento IP IP Durante todo el proceso, los routers leen las direcciones IP de origen y destino para dirigir cada paquete por la ruta correcta.

10. Práctica: ver todo esto en Wireshark

La mejor forma de entender las redes es ver los paquetes de datos reales. Wireshark es una herramienta que captura todo el tráfico que pasa por tu tarjeta de red y te permite examinarlo paquete por paquete.

Ejercicio 1: Capturar un handshake TCP

  1. Abre Wireshark (ya viene instalado en Kali Linux, o instálalo con sudo apt install wireshark).
  2. Selecciona tu interfaz de red (generalmente eth0 o wlan0) y haz clic en el icono de tiburón azul para empezar a capturar.
  3. En otra terminal, ejecuta: curl http://example.com
  4. Vuelve a Wireshark y detén la captura.
  5. En el filtro de visualización (barra superior), escribe: tcp.flags.syn == 1
  6. Verás los paquetes SYN del handshake. Haz clic en uno y observa:
    • En "Transmission Control Protocol" verás las banderas (SYN, ACK, etc.)
    • En "Internet Protocol" verás las IPs de origen y destino
    • El puerto de destino (80 para HTTP)

Ejercicio 2: Ver una consulta DNS

  1. Inicia una nueva captura en Wireshark.
  2. En terminal, ejecuta: nslookup google.com
  3. Detén la captura.
  4. Filtra con: dns
  5. Verás dos paquetes: la consulta (query) y la respuesta (response). En la respuesta podrás ver la IP que resolvió el DNS.

Ejercicio 3: Crear tu cheatsheet de comandos de red

Abre una terminal en Linux y ejecuta cada uno de estos comandos. Anota qué hace y qué muestra:

Comandos esenciales de red 
$ ip a                    # Ver tus interfaces de red e IPs
$ ip route               # Ver la tabla de rutas (a dónde va cada paquete)
$ ping 8.8.8.8           # Verificar conectividad con el DNS de Google
$ traceroute google.com  # Ver los saltos (routers) hasta llegar a Google
$ ss -tulnp              # Ver puertos abiertos en tu máquina
$ nslookup google.com    # Resolver un dominio a IP
$ dig google.com         # Resolución DNS detallada
$ curl -v http://example.com  # Hacer una petición HTTP y ver todo el proceso

Tarea: Ejecuta cada comando, observa la salida, y créate un documento (puede ser un archivo de texto o un .md en GitHub) con el comando, qué hace y un ejemplo de la salida. Este será el inicio de tu cheatsheet personal de ciberseguridad.
