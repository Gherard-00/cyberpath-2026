Fase 4 — Informática Forense y DFIR

Fundamentos de Informática Forense

Cuando ocurre un incidente de seguridad — un ransomware, una filtración de datos, un empleado desleal — alguien tiene que investigar qué pasó. Esa persona es el analista forense. En esta lección aprenderás los fundamentos: qué es la forense digital, cómo se preserva la evidencia, la cadena de custodia, la adquisición de imágenes y el proceso forense completo que usarás en todas las lecciones siguientes.

🔬 1. ¿Qué es la informática forense?

La informática forense (digital forensics) es la disciplina que se encarga de identificar, preservar, analizar y presentar evidencia digital de forma que sea admisible en un proceso legal.

📌 Diferencia con incident response:
  • Incident Response (IR): Prioridad = contener y remediar el incidente RÁPIDO
  • Digital Forensics: Prioridad = preservar evidencia y entender QUÉ pasó exactamente
  • DFIR: La combinación de ambas — el estándar moderno

⚖️ 2. Principios fundamentales

PrincipioDescripción
No alterar la evidenciaNUNCA trabajar directamente sobre el dispositivo original. Siempre crear una copia forense bit a bit.
Documentar todoCada acción que tomes debe quedar registrada: qué hiciste, cuándo, por qué, con qué herramienta.
Cadena de custodiaRegistrar quién tuvo acceso a la evidencia en cada momento.
ReproducibilidadOtro analista con la misma evidencia debe poder llegar a las mismas conclusiones.
Integridad verificableUsar hashes (MD5, SHA-256) para demostrar que la evidencia no fue modificada.

💾 3. Tipos de evidencia digital

TipoEjemplosVolatilidad

🔗 4. Cadena de custodia

La cadena de custodia es el registro documentado de quién ha tenido acceso a la evidencia desde que se recolectó hasta que se presenta en un tribunal.

📌 Un registro de custodia incluye:
  • Fecha y hora de recolección
  • Quién recolectó la evidencia (nombre, rol)
  • Descripción del dispositivo (marca, modelo, serial)
  • Hash de integridad calculado al momento de adquisición
  • Dónde se almacena la evidencia (caja fuerte, servidor seguro)
  • Cada transferencia: quién entregó a quién, fecha, firma

Si la cadena de custodia se rompe (alguien accedió sin registrar, la evidencia estuvo sin custodia), un juez puede invalidar toda la investigación.

⏱️ 5. Orden de volatilidad

Cuando llegas a un incidente, debes recolectar evidencia en orden de volatilidad — primero lo que se pierde más rápido:

    Orden de recolección (de más a menos volátil):
    
    1. 🔴 Registros del CPU, caché           → Se pierden inmediatamente
    2. 🟠 Memoria RAM                        → Se pierde al apagar
    3. 🟡 Estado de red (conexiones, ARP)     → Cambia constantemente
    4. 🟢 Procesos en ejecución              → Cambian al interactuar
    5. 🔵 Disco duro / SSD                   → Persiste (pero puede ser sobreescrito)
    6. 🟣 Logs remotos / backups             → Persisten pero pueden ser rotados
    7. ⬜ Medios físicos (CD, USB, papel)     → Estables

RFC 3227: Guidelines for Evidence Collection — siempre recolectar de lo más volátil a lo menos

📀 6. Adquisición de evidencia

La adquisición es crear una copia exacta (bit a bit) del dispositivo original. Hay dos tipos:

TipoDescripciónHerramientas
Imagen forense (dead)Se apaga el dispositivo y se crea una imagen del disco completodd, dc3dd, FTK Imager
Adquisición en vivo (live)Se recolecta evidencia con el sistema encendido (RAM, procesos, red)DumpIt, WinPMEM, LiME
Adquisición de disco con dd
# Crear imagen forense bit a bit de un disco
$ sudo dd if=/dev/sda of=/evidencia/disco_imagen.raw bs=4096 status=progress

# Con dc3dd (mejor para forense: muestra hash al final)
$ sudo dc3dd if=/dev/sda of=/evidencia/disco.raw hash=sha256 log=adquisicion.log

# Calcular hash de integridad
$ sha256sum /evidencia/disco_imagen.raw
a1b2c3d4e5f6... /evidencia/disco_imagen.raw

# FTK Imager (GUI - Windows) crea formato E01
# E01 es el formato estándar forense (comprimido + con metadatos)
Adquisición de RAM
# En Windows: usar DumpIt (ejecutar como Admin)
C:\> DumpIt.exe
Address space size: 8589934592 (8.00 GB)
Destination: C:\DESKTOP-PC-20260711-143022.raw

# En Linux: usar LiME
$ sudo insmod lime.ko "path=/evidencia/ram.raw format=raw"

# Calcular hash inmediatamente después
$ sha256sum /evidencia/ram.raw

🔐 7. Integridad: hashes y verificación

Los hashes son la columna vertebral de la forense digital. Demuestran que la evidencia no ha sido alterada.

Verificación de integridad
# Calcular hashes de la imagen forense
$ md5sum disco_imagen.raw
$ sha256sum disco_imagen.raw

# ANTES de analizar: verificar que el hash coincide
$ sha256sum disco_imagen.raw
a1b2c3d4e5f6...  disco_imagen.raw
# ¿Coincide con el hash original? ✅ → Evidencia íntegra

# Si el hash cambia → ❌ La evidencia fue modificada
# Esto invalida el análisis en un tribunal

📊 8. El proceso forense completo

    Proceso Forense (NIST SP 800-86):
    
    1. IDENTIFICACIÓN     → ¿Qué dispositivos contienen evidencia relevante?
           ↓
    2. PRESERVACIÓN       → Aislar y proteger la evidencia (bloqueador de escritura)
           ↓
    3. ADQUISICIÓN        → Crear copias forenses bit a bit + calcular hashes
           ↓
    4. ANÁLISIS           → Examinar la copia forense con herramientas especializadas
           ↓
    5. DOCUMENTACIÓN      → Registrar CADA hallazgo con timestamps y contexto
           ↓
    6. PRESENTACIÓN       → Reporte final para cliente / tribunal / management

Cada fase tiene sus reglas estrictas — saltarse una puede invalidar la investigación
