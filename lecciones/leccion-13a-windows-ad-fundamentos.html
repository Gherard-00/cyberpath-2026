Fase 3 — Red Team y Técnicas Avanzadas

Fundamentos de Windows y Active Directory — Lo que necesitas antes de atacar

Si Linux es el taller del mecánico, Windows es la flota de coches corporativos que vas a auditar. El 95% de las empresas Fortune 1000 usan Active Directory. Antes de aprender ataques como Kerberoasting o Pass-the-Hash, necesitas entender cómo funciona el sistema que vas a atacar. En esta lección aprenderás la estructura de un dominio Windows, qué son los usuarios, grupos, GPOs y Domain Controllers — todo con analogías claras.

1. ¿Por qué Windows importa en ciberseguridad?

Hasta ahora has trabajado casi exclusivamente con Linux. Pero en el mundo real, la gran mayoría de las redes corporativas corren sobre Windows. Los empleados usan Windows 10/11, los servidores corren Windows Server, y todo está conectado mediante Active Directory.

Analogía: La empresa como un edificio corporativo

Imagina una empresa como un edificio de oficinas. Cada empleado tiene una credencial (badge) que le da acceso a ciertas áreas. Hay un departamento de seguridad (el Domain Controller) que gestiona todas las credenciales, decide quién entra a dónde, y aplica las reglas del edificio (las GPOs). Active Directory es ese departamento de seguridad — centralizado, poderoso, y si lo controlas, controlas todo el edificio.

¿Por qué es relevante para pentesting? Porque si logras comprometer un usuario del dominio, puedes escalar privilegios hasta llegar a Domain Admin — el equivalente a tener la llave maestra de todo el edificio.

2. Estructura de un dominio Windows

Un dominio de Windows es un grupo de computadoras, usuarios y recursos administrados centralmente. Todos comparten la misma base de datos de seguridad.

Analogía: El organigrama de una multinacional

Un bosque (forest) es la multinacional completa. Dentro hay árboles (trees), que son las divisiones regionales. Cada árbol tiene dominios, que son las oficinas locales. Y dentro de cada dominio hay Unidades Organizativas (OUs), que son los departamentos: Ventas, IT, RRHH. Todos comparten cierto nivel de confianza (trusts) entre sí.

3. Usuarios, Grupos y Permisos

En Active Directory, cada persona, computadora y servicio es un objeto con un identificador único llamado SID (Security Identifier). Los permisos se asignan a través de grupos.

Tipos de cuentas

  • Cuentas de usuario: Para personas reales (ej: jgarcia@empresa.local)
  • Cuentas de servicio: Para aplicaciones y servicios (ej: svc_sql, svc_backup) — objetivos valiosos en ataques
  • Cuentas de equipo: Cada PC unida al dominio tiene su propia cuenta (ej: DESKTOP-ABC123$)

Grupos predefinidos críticos

GrupoDescripción¿Por qué importa?
Domain AdminsAdministradores totales del dominio. Acceso a todo.El objetivo final de un atacante. Si llegas aquí, controlas todo.
Enterprise AdminsAdministradores de todo el bosque (multi-dominio).Nivel máximo. Solo existe en el dominio raíz del bosque.
Domain UsersTodos los usuarios del dominio son miembros.Un usuario normal puede enumerar MUCHA información del dominio por defecto.
Administrators (local)Admins locales de una máquina específica.Admin local ≠ Domain Admin, pero puede ser un paso hacia allá.
Backup OperatorsPueden hacer backup de archivos, incluyendo NTDS.dit.Si comprometes este grupo, puedes extraer TODOS los hashes del dominio.

⚠️ Error común de principiante

Admin local ≠ Domain Admin. Ser administrador de tu PC no significa que tengas control del dominio. Sin embargo, un admin local puede extraer credenciales de la memoria (mimikatz) y escalar hasta Domain Admin si las credenciales correctas están cacheadas.

SID: el identificador único

Cada objeto en AD tiene un SID (Security Identifier) único. Los permisos internos se resuelven por SID, no por nombre.

4. Group Policy Objects (GPOs)

Las GPOs son reglas que se aplican automáticamente a usuarios y computadoras del dominio. Son el mecanismo central de control en una red Windows.

Analogía: Las reglas del edificio

Las GPOs son como las políticas internas de la empresa: "todos deben cambiar su contraseña cada 90 días", "nadie puede instalar software sin autorización", "las pantallas se bloquean después de 5 minutos". Se aplican automáticamente a todos o a grupos específicos — no puedes elegir ignorarlas.

Ejemplos comunes de GPOs

GPOQué haceRelevancia para pentesting
Password PolicyLongitud mínima, complejidad, historial, expiraciónContraseñas débiles = fuerza bruta más fácil
Account LockoutBloquea cuenta después de X intentos fallidosSi hay lockout, la fuerza bruta es más lenta/riesgosa
Software RestrictionControla qué aplicaciones pueden ejecutarsePuede bloquear tus herramientas de pentesting
Audit PolicyQué eventos se registran en los logsLogs activos = mayor riesgo de detección
Startup/Logon ScriptsScripts que se ejecutan al iniciar sesión o encender la PCSi los puedes modificar, tienes persistencia automática

Dato clave para pentesting

Las GPOs se almacenan en la carpeta \\dominio\SYSVOL, accesible por cualquier usuario del dominio. A veces contienen contraseñas en texto plano en archivos XML (Group Policy Preferences) — una vulnerabilidad clásica conocida como GPP Passwords.

5. ¿Qué es un Domain Controller?

El Domain Controller (DC) es el servidor que gestiona TODO el dominio. Es el cerebro de Active Directory.

Analogía: El registro civil + la comisaría + el banco central

El Domain Controller es todo a la vez: el registro civil (sabe quién es cada persona), la comisaría (decide quién tiene permiso de hacer qué), y el banco central (guarda todas las credenciales). Si un atacante lo compromete, controla todo el dominio.

Componentes críticos de un DC

ComponenteFunciónPuerto
NTDS.ditBase de datos con TODOS los hashes de contraseñas del dominioN/A (archivo en disco)
Kerberos (KDC)Servicio de autenticación que emite tickets88
LDAPProtocolo para consultar información del directorio389 / 636 (SSL)
DNSResolución de nombres — AD depende totalmente de DNS53
SMB/CIFSCompartir archivos, SYSVOL, NETLOGON445
RPCComunicación entre servicios135 + dinámicos

⚠️ NTDS.dit: El Santo Grial

NTDS.dit contiene los hashes de TODAS las contraseñas del dominio. Si un atacante obtiene este archivo (vía DCSync, backup, o acceso al DC), puede crackear o usar Pass-the-Hash para autenticarse como CUALQUIER usuario, incluyendo Domain Admin.

6. Herramientas de administración

Conocer las herramientas de administración de Windows te permite entender qué hace un administrador legítimo — y cómo un atacante abusa de las mismas herramientas.

PowerShell para Active Directory

Comandos de PowerShell para AD
# Ver información del dominio
PS> Get-ADDomain

# Listar todos los usuarios del dominio
PS> Get-ADUser -Filter * -Properties * | Select Name, SamAccountName, Enabled

# Listar todos los grupos
PS> Get-ADGroup -Filter * | Select Name

# Ver miembros de Domain Admins
PS> Get-ADGroupMember "Domain Admins" | Select Name

# Buscar cuentas de servicio (con SPN)
PS> Get-ADUser -Filter {ServicePrincipalName -ne "$null"} -Properties ServicePrincipalName

# Ver GPOs aplicadas
PS> Get-GPO -All | Select DisplayName, GpoStatus

# Ver la política de contraseñas
PS> Get-ADDefaultDomainPasswordPolicy

Importante: Cualquier usuario del dominio puede ejecutar la mayoría de estos comandos de consulta. Esta es la razón por la que la enumeración de AD es tan poderosa — el diseño del sistema permite que cualquier usuario autenticado lea mucha información.

Herramientas gráficas

  • Active Directory Users and Computers (ADUC): Interfaz gráfica para gestionar usuarios, grupos y OUs
  • Group Policy Management Console (GPMC): Para crear y gestionar GPOs
  • Server Manager: Panel central de administración de Windows Server
  • RSAT (Remote Server Administration Tools): Herramientas para administrar AD desde una estación de trabajo
