Fase 4 — Informática Forense y DFIR

Wireshark — Análisis de tráfico de red y detección de amenazas

Wireshark es el analizador de protocolos de red más utilizado del mundo. Te permite capturar y analizar cada paquete que pasa por tu red en tiempo real. En ciberseguridad lo usamos para detectar escaneos de puertos, identificar exfiltración de datos, analizar tráfico malicioso, y reconstruir exactamente qué pasó durante un incidente de seguridad.

1. ¿Qué es Wireshark?

Wireshark captura tráfico de red a nivel de paquetes y te permite inspeccionarlos con detalle extremo: cabeceras Ethernet, IP, TCP/UDP, y protocolos de aplicación (HTTP, DNS, SMB, etc.).

UsoDescripción
Análisis forense de redInvestigar un PCAP capturado durante un incidente
Detección de amenazasIdentificar escaneos, malware, C2 beaconing
TroubleshootingDiagnosticar problemas de red y rendimiento
PentestingCapturar credenciales en protocolos inseguros
AprendizajeEntender cómo funcionan los protocolos de red

2. La interfaz de Wireshark

Paneles principales:
  • Packet List (arriba): Lista de todos los paquetes capturados (número, tiempo, origen, destino, protocolo, info)
  • Packet Details (medio): Desglose del paquete seleccionado capa por capa (Ethernet → IP → TCP → HTTP)
  • Packet Bytes (abajo): Los bytes crudos del paquete en hexadecimal y ASCII
  • Display Filter Bar (superior): Donde escribes tus filtros de visualización
Colores importantes:
  • 🟢 Verde: Tráfico TCP normal
  • 🔵 Azul claro: Tráfico UDP (DNS, etc.)
  • 🟡 Amarillo: Tráfico HTTP
  • 🔴 Rojo/Negro: Errores TCP (RST, retransmisiones)
  • ⚫ Negro con fondo rojo: Problemas graves

Captura de tráfico
# Abrir Wireshark

# 2. Click en el ícono de aleta de tiburón (Start Capturing)
# 3. Para detener: click en el cuadrado rojo (Stop)

# Guardar la captura: File → Save As → archivo.pcapng

# Abrir un PCAP existente (de un caso forense):
# File → Open → seleccionar el archivo .pcap o .pcapng

# Capturar desde terminal con dumpcap:
$ dumpcap -i eth0 -w captura.pcapng

4. Filtros de captura vs filtros de visualización

TipoCuándo se aplicaSintaxisEjemplo
Filtro de capturaANTES de capturar — descarta paquetes que no coincidenBPF (Berkeley Packet Filter)host 10.10.10.5 and port 80
Filtro de visualizaciónDESPUÉS de capturar — oculta paquetes del listadoSintaxis propia de Wiresharkip.addr == 10.10.10.5 && tcp.port == 80

En análisis forense, generalmente trabajas con PCAPs ya capturados, por lo que usarás filtros de visualización el 95% del tiempo.

5. Filtros de visualización esenciales

FiltroQué muestra
ip.addr == 10.10.10.5Todo el tráfico de/hacia esa IP
ip.src == 10.10.10.5Solo tráfico DESDE esa IP
ip.dst == 10.10.10.5Solo tráfico HACIA esa IP
tcp.port == 443Tráfico TCP en puerto 443 (HTTPS)
udp.port == 53Tráfico DNS
httpSolo tráfico HTTP
dnsSolo consultas/respuestas DNS
tcp.flags.syn == 1 && tcp.flags.ack == 0Solo paquetes SYN (inicio de conexión / escaneo)
tcp.flags.rst == 1Paquetes RST (conexión rechazada / puerto cerrado)
http.request.method == "POST"Solo peticiones POST (posible exfiltración)
frame contains "password"Paquetes que contienen la palabra "password"
!(arp or dns or icmp)Excluir tráfico "ruidoso" para ver lo interesante
tcp.stream eq 5Toda la conversación TCP #5
Tip: Puedes combinar filtros con && (AND), || (OR), y ! (NOT). Ejemplo: ip.addr == 10.10.10.5 && http && !(http.response.code == 200)

6. Analizar conversaciones TCP

Follow TCP Stream
# La función más poderosa de Wireshark:
# Clic derecho en cualquier paquete → Follow → TCP Stream

# Esto reconstruye TODA la conversación entre cliente y servidor
# El texto en ROJO es lo que envió el cliente
# El texto en AZUL es lo que respondió el servidor

# Ejemplo: login FTP en texto plano
USER admin
331 Password required for admin
PASS SuperSecretPassword123
230 User admin logged in

# ¡Contraseña capturada en texto plano!
Statistics → Conversations: Muestra un resumen de TODAS las conversaciones (quién habló con quién, cuántos bytes, duración). Muy útil para identificar las conexiones más voluminosas (posible exfiltración).

8. Analizar tráfico DNS

Análisis DNS
# Filtrar todo el tráfico DNS
dns

# Solo consultas (no respuestas)
dns.flags.response == 0

# Buscar dominios sospechosos
dns.qry.name contains "evil"

# 🚩 Señales de exfiltración por DNS:
# - Consultas a dominios con subdominios MUY largos:
#   aGVsbG8gd29ybGQ=.datos.evil.com  (datos codificados en base64)
# - Volumen alto de consultas TXT a un mismo dominio
# - Consultas a dominios recién registrados (DGA)

# Buscar consultas DNS con subdominios largos (posible exfiltración)
dns.qry.name.len > 50

9. Detectar escaneos de puertos (Nmap)

Detectar Nmap
# SYN Scan (el más común de Nmap):
# Muchos paquetes SYN desde la misma IP a diferentes puertos
tcp.flags.syn == 1 && tcp.flags.ack == 0

# Si ves cientos de SYN desde una IP → escaneo de puertos
# Statistics → Conversations → TCP → ordenar por paquetes

# Puerto abierto: SYN → SYN-ACK → RST (Nmap no completa la conexión)
# Puerto cerrado: SYN → RST-ACK

# Detectar ICMP scan (ping sweep):
icmp.type == 8  # Echo requests

# Detectar NULL/FIN/XMAS scans:
tcp.flags == 0x000  # NULL scan (sin flags)
tcp.flags.fin == 1 && tcp.flags.syn == 0  # FIN scan

10. Detectar exfiltración de datos

🚩 Señales de exfiltración:
  • Volumen anómalo: Una estación de trabajo enviando GBs hacia afuera (Statistics → Endpoints → ordenar por Tx Bytes)
  • Beaconing: Conexiones a intervalos regulares al mismo destino (cada 30s, 1min) → típico de C2
  • DNS tunneling: Consultas DNS con subdominios inusualmente largos
  • ICMP tunneling: Paquetes ICMP con payloads anormalmente grandes
  • Destinos sospechosos: Conexiones a IPs en países donde la empresa no opera
  • HTTP POST grandes: Uploads masivos a dominios desconocidos
Detectar beaconing
# Buscar conexiones repetitivas al mismo destino
ip.dst == 185.99.2.3

# Statistics → IO Graph
# Si ves picos de tráfico a intervalos regulares → beaconing

# Buscar ICMP con payloads grandes (posible tunnel)
icmp && data.len > 100

11. Extraer archivos y credenciales

Extracción
# Extraer TODOS los archivos transferidos por HTTP:
# File → Export Objects → HTTP → Save All

# Extraer archivos de SMB:
# File → Export Objects → SMB → Save All

# Extraer archivos de FTP:
# Follow TCP Stream del canal de datos (puerto 20)
# Show data as: Raw → Save As

# Buscar credenciales en texto plano:
http.authbasic  # HTTP Basic Auth
ftp.request.command == "PASS"  # Contraseñas FTP
smtp.req.parameter contains "@"  # Credenciales SMTP

# Buscar cualquier texto que contenga "password"
frame contains "password"

12. tshark: Wireshark en la terminal

tshark
# Capturar tráfico en la terminal
$ tshark -i eth0

# Capturar solo HTTP y guardar
$ tshark -i eth0 -f "port 80" -w captura_http.pcapng

# Leer un PCAP con filtro de visualización
$ tshark -r captura.pcapng -Y "http.request"

# Extraer campos específicos (útil para scripts)
$ tshark -r captura.pcapng -Y "dns" -T fields -e dns.qry.name | sort | uniq -c | sort -rn

# Top 10 dominios DNS más consultados
    247 evil-c2.com
     85 updates.windows.com
     42 google.com
# 247 consultas a evil-c2.com → ¡Definitivamente C2!

# Extraer todas las URLs HTTP
$ tshark -r captura.pcapng -Y "http.request" -T fields -e http.host -e http.request.uri
