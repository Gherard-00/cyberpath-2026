1. ¿Qué es Linux y por qué se usa en ciberseguridad?

Linux es un sistema operativo de código abierto (open source) creado en 1991 por Linus Torvalds. A diferencia de Windows o macOS, Linux es gratuito, cualquiera puede ver y modificar su código fuente, y existen cientos de versiones (llamadas distribuciones o "distros") adaptadas a diferentes necesidades.

Analogía: Linux es como los planos de un edificio que son públicos

Imagina que los planos de un edificio fueran públicos: cualquier arquitecto podría construir su propia versión, mejorarla, adaptarla a sus necesidades. Eso es Linux — un núcleo (kernel) que cualquiera puede tomar y construir su propia versión del sistema operativo. Por eso existen Ubuntu, Fedora, Kali Linux, Arch Linux, etc.

¿Por qué Linux para ciberseguridad?

  • Kali Linux viene con +600 herramientas de hacking pre-instaladas (Nmap, Metasploit, Burp Suite, Wireshark, etc.).
  • La mayoría de servidores en Internet corren Linux (más del 90%). Si quieres atacar o defender servidores, necesitas entender Linux.
  • Control total: puedes ver todos los procesos, archivos, conexiones de red, logs — nada se te esconde.
  • La terminal es más poderosa que cualquier GUI: puedes automatizar tareas, crear herramientas, analizar datos masivos.
  • Es gratuito y personalizable: no necesitas licencias ni pagar nada.

Distribuciones que usarás en este curso

Distribución Basada en ¿Para qué la usamos?

Ubuntu Server Debian Para montar servidores de práctica (laboratorio).

2. La terminal: tu herramienta principal

La terminal (también llamada shell, consola o línea de comandos) es donde escribes comandos de texto para decirle a Linux qué hacer. En lugar de hacer clic en iconos, escribes instrucciones. Parece intimidante al principio, pero una vez que la dominas, es infinitamente más rápida y poderosa que cualquier interfaz gráfica.

Analogía: La terminal vs. la GUI

Usar la GUI (interfaz gráfica) es como conducir un auto automático: fácil pero limitado. Usar la terminal es como conducir un auto de carreras manual: necesitas aprender, pero tienes control absoluto sobre todo. En ciberseguridad, necesitas el auto de carreras.

La estructura de un comando

Todos los comandos en Linux siguen esta estructura básica:

Anatomía de un comando Linux 
$ comando  -opciones  argumento

# Ejemplo real:
$ ls       -la        /etc

# Desglose:
  ls       → el COMANDO: "listar archivos"
  -la      → las OPCIONES: -l (formato largo) + -a (mostrar ocultos)
  /etc     → el ARGUMENTO: "en el directorio /etc"

El $ (o # si eres root) es el prompt: indica que la terminal está lista para recibir un comando. No lo escribes tú — ya está ahí.

3. El sistema de archivos de Linux

En Windows, todo empieza en C:\. En Linux, todo empieza en / (la raíz o "root"). No hay letras de unidad. Todo — archivos, dispositivos, procesos — se representa como archivos dentro de una estructura de directorios.

La estructura de directorios de Linux

Árbol de directorios principal 
/                     ← La raíz. TODO parte de aquí
├── /bin              ← Comandos esenciales (ls, cat, cp, mv, rm...)
├── /sbin             ← Comandos del sistema (solo root: iptables, fdisk...)
├── /etc              ← Archivos de configuración del sistema
│   ├── /etc/passwd   ← Lista de usuarios del sistema
│   ├── /etc/shadow   ← Hashes de contraseñas (solo root puede leerlo)
│   ├── /etc/hosts    ← Resolución local de nombres (como un DNS manual)
│   └── /etc/ssh/     ← Configuración del servidor SSH
├── /home             ← Directorios personales de cada usuario
│   └── /home/kali    ← Tu directorio personal (~ es un atajo)
├── /root             ← Directorio personal del usuario root
├── /var              ← Datos variables: logs, caché, bases de datos
│   └── /var/log      ← LOGS del sistema — fundamental en forense
├── /tmp              ← Archivos temporales (se borran al reiniciar)
├── /opt              ← Software de terceros instalado manualmente
├── /dev              ← Dispositivos del sistema (discos, USB, etc.)
├── /proc             ← Información de procesos en ejecución (virtual)
└── /usr              ← Programas y utilidades del usuario
    └── /usr/bin      ← Más comandos (python3, nmap, etc.)

Directorios clave para ciberseguridad: /etc/passwd y /etc/shadow (usuarios y contraseñas), /var/log (logs para forense), /tmp (atacantes dejan archivos aquí), /proc (información de procesos en vivo).

Rutas absolutas vs. relativas

Tipo Empieza con Ejemplo Significado
Absoluta / /home/kali/tools/nmap.txt La ruta completa desde la raíz. Siempre funciona, no importa dónde estés.
Relativa Sin / tools/nmap.txt Relativa al directorio donde estás ahora. Si estás en /home/kali, es lo mismo que la absoluta.
Atajos de navegación 
$ cd ~          # Ir a tu directorio home (/home/kali)
$ cd ..         # Subir un directorio (ir al padre)
$ cd ../..      # Subir dos directorios
$ cd -          # Volver al directorio anterior
$ cd /          # Ir a la raíz

4. Manipulación de archivos y directorios

En Linux, casi todo lo que haces es crear, mover, copiar, borrar y buscar archivos. Estos son los comandos que usarás miles de veces:

Crear archivos y directorios

Crear archivos y directorios 
# Crear un archivo vacío
$ touch notas.txt

# Crear un archivo con contenido
$ echo "Mi primera nota" > notas.txt

# Agregar contenido sin borrar lo anterior (>>)
$ echo "Segunda línea" >> notas.txt

# Crear un directorio
$ mkdir herramientas

# Crear directorios anidados de una vez
$ mkdir -p proyectos/pentesting/reportes

Importante: > sobreescribe el archivo (cuidado, borra todo lo anterior). >> agrega al final sin borrar nada. Esta es una diferencia crítica.

Copiar, mover y renombrar

Copiar y mover archivos 
# Copiar un archivo
$ cp notas.txt backup_notas.txt

# Copiar un directorio completo (necesitas -r: recursive)
$ cp -r herramientas/ backup_herramientas/

# Mover un archivo a otro directorio
$ mv notas.txt herramientas/

# Renombrar un archivo (mv también sirve para renombrar)
$ mv notas.txt apuntes.txt

# Eliminar un archivo
$ rm archivo.txt

# Eliminar un directorio y todo su contenido
$ rm -rf directorio/
# ⚠️ CUIDADO: rm -rf no pide confirmación y no tiene papelera

⚠️ Nunca ejecutes rm -rf / — borraría TODO el sistema. Es uno de los comandos más peligrosos que existen. Siempre verifica la ruta antes de usar rm -rf.

Ver contenido de archivos

Comando ¿Qué hace? ¿Cuándo usarlo?
cat archivoMuestra TODO el contenido de una vezArchivos pequeños
less archivoMuestra contenido con scroll (q para salir)Archivos grandes (logs)
head -n 20 archivoMuestra las primeras 20 líneasVer el inicio de un log
tail -n 20 archivoMuestra las últimas 20 líneasVer los eventos más recientes
tail -f archivoMuestra en tiempo real las nuevas líneasMonitorear un log en vivo
wc -l archivoCuenta las líneas del archivoSaber el tamaño de un diccionario

Buscar archivos y texto

Buscar archivos y contenido 
# Buscar un archivo por nombre en todo el sistema
$ find / -name "passwd" 2>/dev/null

# Buscar archivos por extensión
$ find /home -name "*.txt"

# Buscar archivos modificados en los últimos 7 días
$ find /var/log -mtime -7

# Buscar texto DENTRO de archivos (grep = Global Regular Expression Print)
$ grep "error" /var/log/syslog

# Buscar texto ignorando mayúsculas/minúsculas
$ grep -i "password" /etc/config.txt

# Buscar recursivamente en todos los archivos de un directorio
$ grep -r "admin" /var/www/

¿Qué es 2>/dev/null? Redirige los mensajes de error a la "nada". Cuando usas find / sin ser root, recibes muchos errores "permiso denegado" — con 2>/dev/null los ocultas y solo ves los resultados útiles.

El Pipe ( | ) — Encadenar comandos

El pipe | toma la salida de un comando y la pasa como entrada al siguiente. Es una de las herramientas más poderosas de Linux:

cat /etc/passwd | grep "bash" — Muestra solo los usuarios que usan bash como shell.
ls -la | wc -l — Cuenta cuántos archivos hay en el directorio.
history | grep "nmap" — Busca en tu historial todos los comandos que incluyen "nmap".
cat access.log | sort | uniq -c | sort -rn | head — Analiza un log: ordena, cuenta repetidos y muestra los más frecuentes.

5. Permisos: quién puede hacer qué

En Linux, cada archivo y directorio tiene permisos que definen quién puede leerlo, escribirlo o ejecutarlo. Entender los permisos es absolutamente fundamental para la ciberseguridad: una mala configuración de permisos es una de las vulnerabilidades más comunes que encontrarás en pentesting.

Los tres tipos de permisos

Permiso Letra Valor numérico En archivos En directorios
Lectura r 4 Puedes ver el contenido del archivo Puedes listar su contenido (ls)
Escritura w 2 Puedes modificar el archivo Puedes crear/borrar archivos dentro
Ejecución x 1 Puedes ejecutarlo como programa Puedes entrar al directorio (cd)

Cómo leer los permisos

Interpretando ls -la 
$ ls -la /etc/passwd /etc/shadow

-rw-r--r-- 1 root root  2847 Jul  9 10:30 /etc/passwd
-rw-r----- 1 root shadow 1423 Jul  9 10:30 /etc/shadow

# Desglose de "-rw-r--r--":

 -    rw-    r--    r--
 │    │      │      │
 │    │      │      └── Otros (everyone): solo lectura (r--)
 │    │      └── Grupo: solo lectura (r--)
 │    └── Propietario (root): lectura + escritura (rw-)
 └── Tipo: - = archivo, d = directorio, l = enlace simbólico

# /etc/passwd → Todos pueden LEER (por eso es rw-r--r--)
# /etc/shadow → Solo root y grupo shadow pueden leer (rw-r-----)
# Por eso /etc/shadow es más sensible: contiene los hashes

En ciberseguridad: /etc/passwd es legible por todos y contiene la lista de usuarios (pero NO las contraseñas). /etc/shadow contiene los hashes de las contraseñas y solo root puede leerlo. Si un atacante logra leer /etc/shadow, puede intentar crackear las contraseñas offline.

Cambiar permisos: chmod

chmod — Cambiar permisos 
# Forma numérica (la más usada en la práctica)
# Cada dígito = propietario + grupo + otros
# r=4, w=2, x=1 → se suman

$ chmod 755 mi_script.sh
# 7 = rwx (4+2+1) → propietario: todo
# 5 = r-x (4+0+1) → grupo: leer y ejecutar
# 5 = r-x (4+0+1) → otros: leer y ejecutar

$ chmod 644 documento.txt
# 6 = rw- → propietario: leer y escribir
# 4 = r-- → grupo: solo leer
# 4 = r-- → otros: solo leer

$ chmod 600 clave_privada.pem
# 6 = rw- → solo el propietario puede leer/escribir
# 0 = --- → nadie más tiene acceso

# Forma simbólica
$ chmod +x script.sh       # Agregar permiso de ejecución para todos
$ chmod u+x script.sh      # Solo para el propietario (u=user)
$ chmod go-rw secreto.txt  # Quitar lectura y escritura a grupo y otros

⚠️ Permisos peligrosos — Lo que buscarás en pentesting

chmod 777 — Cualquiera puede leer, escribir y ejecutar. Si encuentras archivos con permisos 777, es una mala configuración de seguridad.
Archivos SUID (-rwsr-xr-x): El bit s significa que el archivo se ejecuta con los privilegios del propietario (generalmente root). Los archivos SUID mal configurados son uno de los principales vectores de escalada de privilegios en Linux.
Comando para buscar archivos SUID: find / -perm -4000 2>/dev/null

6. Usuarios y grupos

Linux es un sistema multiusuario: varias personas (o servicios) pueden usar el mismo sistema, cada uno con su propio nivel de acceso. Entender cómo funcionan los usuarios es crítico porque la escalada de privilegios (pasar de usuario normal a root) es una de las fases más importantes del pentesting.

Tipos de usuarios

Tipo UID Descripción
root 0 El superusuario. Puede hacer CUALQUIER cosa. Es como el administrador de Windows pero aún más poderoso.
Usuarios del sistema 1-999 Creados automáticamente para servicios (apache, mysql, sshd). No son personas reales.
Usuarios normales 1000+ Personas reales que usan el sistema (kali, juan, etc.).
Comandos de gestión de usuarios 
# Ver tu usuario actual
$ whoami
kali

# Ver información detallada de tu usuario
$ id
uid=1000(kali) gid=1000(kali) groups=1000(kali),27(sudo)

# Ver todos los usuarios del sistema
$ cat /etc/passwd | cut -d: -f1

# Ejecutar un comando como root (te pide contraseña)
$ sudo apt update

# Convertirte en root permanentemente
$ sudo su -
root@kali:~#  ← El prompt cambia a # cuando eres root

# Crear un nuevo usuario
$ sudo adduser nuevo_usuario

# Cambiar la contraseña de un usuario
$ sudo passwd nuevo_usuario

# Agregar un usuario al grupo sudo (darle poderes de root)
$ sudo usermod -aG sudo nuevo_usuario

sudo significa "Super User DO" — ejecuta un comando con privilegios de root. Solo funciona si tu usuario pertenece al grupo sudo. En pentesting, si logras acceso a un usuario que está en el grupo sudo, prácticamente eres root.

El archivo /etc/passwd explicado

Cada línea de /etc/passwd tiene esta estructura:

kali:x:1000:1000:Kali User:/home/kali:/bin/bash

kali → nombre de usuario
x → la contraseña está en /etc/shadow (antes se guardaba aquí, por eso el archivo se llama "passwd")
1000 → UID (User ID)
1000 → GID (Group ID)
Kali User → descripción/nombre completo
/home/kali → directorio home
/bin/bash → shell asignada (si dice /bin/false o /usr/sbin/nologin, el usuario no puede hacer login)

7. Procesos: programas en ejecución

Cada programa que se ejecuta en Linux se convierte en un proceso con un número de identificación único llamado PID (Process ID). Saber ver y controlar procesos es esencial: en forense digital necesitarás identificar procesos maliciosos, y en pentesting podrás ver qué servicios están corriendo.

Comandos para gestionar procesos 
# Ver tus procesos actuales
$ ps

# Ver TODOS los procesos del sistema con detalles
$ ps aux

# Ver procesos en tiempo real (como el Task Manager de Windows)
$ top
# (o mejor aún, instala htop: sudo apt install htop)
$ htop

# Buscar un proceso específico
$ ps aux | grep apache
# root  1234  0.0  1.2  Apache2: httpd

# Matar un proceso por PID
$ kill 1234

# Matar un proceso a la fuerza (si no responde)
$ kill -9 1234

# Matar todos los procesos con ese nombre
$ killall firefox

# Ejecutar un comando en segundo plano
$ nmap -sS 10.0.2.15 &
# El & al final lo envía al background

# Ver trabajos en segundo plano
$ jobs

# Ver qué puertos están siendo usados por qué procesos
$ ss -tulnp
# Esto es MUY útil: te muestra qué servicios escuchan en qué puertos

En pentesting: ps aux te ayuda a descubrir qué servicios corren en una máquina comprometida. ss -tulnp te muestra qué puertos están abiertos y qué programa los usa. En forense, ps y /proc te ayudan a identificar procesos maliciosos o sospechosos.

8. Gestión de paquetes: instalar y actualizar software

En Linux, el software se instala mediante un gestor de paquetes (package manager). Es como una tienda de apps pero desde la terminal. En Kali Linux (basado en Debian), el gestor principal es APT (Advanced Package Tool).

Comandos APT esenciales 
# Actualizar la lista de paquetes disponibles
$ sudo apt update

# Actualizar todos los paquetes instalados a su última versión
$ sudo apt upgrade -y

# Hacer ambas cosas de una vez
$ sudo apt update && sudo apt upgrade -y

# Instalar un programa
$ sudo apt install nmap

# Instalar varios programas a la vez
$ sudo apt install nmap gobuster nikto

# Desinstalar un programa
$ sudo apt remove nmap

# Buscar si un programa está disponible
$ apt search wireshark

# Ver información de un paquete
$ apt show nmap

# Limpiar paquetes que ya no se necesitan
$ sudo apt autoremove

&& encadena dos comandos: el segundo solo se ejecuta si el primero fue exitoso. -y responde "sí" automáticamente a las confirmaciones. Siempre ejecuta apt update antes de apt install para asegurarte de tener la lista de paquetes actualizada.

¿Qué es un "paquete"?

Un paquete es un programa empaquetado junto con sus dependencias (otros programas que necesita para funcionar). Es como un archivo .exe de Windows pero más organizado: el sistema sabe qué instaló, a dónde fueron los archivos, y puede desinstalarlo limpiamente. En Debian/Kali, los paquetes tienen extensión .deb.

9. Editores de texto: nano y vim

En muchas situaciones (configurar servicios, editar scripts, modificar archivos de configuración) necesitarás un editor de texto en la terminal. Los dos más usados son nano (fácil) y vim (poderoso).

nano — El editor fácil

Usar nano 
# Abrir/crear un archivo con nano
$ nano mi_script.sh

# Dentro de nano:
# - Escribe normalmente, como en un bloc de notas
# - Ctrl + O  → Guardar
# - Ctrl + X  → Salir
# - Ctrl + K  → Cortar línea
# - Ctrl + U  → Pegar línea
# - Ctrl + W  → Buscar texto
# - Ctrl + G  → Ayuda

vim — El editor poderoso

Vim es más complejo pero infinitamente más poderoso. Lo encontrarás en prácticamente todos los servidores Linux, así que al menos debes saber lo básico: cómo entrar, escribir, guardar y salir.

Supervivencia en vim 
# Abrir un archivo con vim
$ vim archivo.txt

# Vim tiene DOS MODOS principales:
# 1. Modo NORMAL (por defecto): para navegar y ejecutar comandos
# 2. Modo INSERT: para escribir texto

Comandos esenciales:

  i          → Entrar a modo INSERT (ahora puedes escribir)
  Esc        → Volver a modo NORMAL
  :w         → Guardar
  :q         → Salir (solo si no hay cambios sin guardar)
  :wq        → Guardar y salir
  :q!        → Salir SIN guardar (fuerza la salida)
  dd         → Borrar una línea completa (en modo NORMAL)
  yy         → Copiar una línea
  p          → Pegar
  /texto     → Buscar "texto" en el archivo
  u          → Deshacer (undo)

¡Lo más importante: para salir de vim presiona Esc, luego escribe :q! y Enter!

El chiste de "cómo salir de vim" es un meme legendario entre programadores porque es genuinamente confuso la primera vez. Ahora ya lo sabes: Esc → :q! → Enter.

10. Bash scripting: automatiza tu trabajo

Un script de Bash es un archivo de texto con una serie de comandos que se ejecutan automáticamente, uno tras otro. En lugar de escribir 20 comandos a mano, los pones en un script y lo ejecutas con un solo comando. En ciberseguridad, los scripts son esenciales: para automatizar escaneos, procesar logs, crear herramientas rápidas, etc.

Tu primer script

mi_primer_script.sh 
#!/bin/bash
# ↑ Shebang: le dice al sistema que use Bash para ejecutar este script

# Mi primer script de ciberseguridad
echo "=============================="
echo "  Información del Sistema"
echo "=============================="
echo ""
echo "Usuario actual:   $(whoami)"
echo "Hostname:         $(hostname)"
echo "Sistema:          $(uname -o)"
echo "Kernel:           $(uname -r)"
echo "Fecha:            $(date)"
echo "IP local:         $(hostname -I | awk '{print $1}')"
echo "Usuarios logueados: $(who | wc -l)"
echo ""
echo "=============================="

Para ejecutar este script:

1. Créalo con nano mi_primer_script.sh y pega el contenido.

2. Dale permiso de ejecución: chmod +x mi_primer_script.sh

3. Ejecútalo: ./mi_primer_script.sh

$(comando) ejecuta un comando y pone su resultado en ese lugar. Se llama command substitution.

Variables

Variables en Bash 
#!/bin/bash

# Definir variables (SIN espacios alrededor del =)
nombre="CyberPath"
version=2026
ip_objetivo="10.0.2.15"

# Usar variables con $
echo "Bienvenido a $nombre versión $version"
echo "Escaneando objetivo: $ip_objetivo"

# Guardar la salida de un comando en una variable
mi_ip=$(hostname -I | awk '{print $1}')
echo "Mi IP es: $mi_ip"

# Leer input del usuario
read -p "Introduce la IP objetivo: " target
echo "Vas a escanear: $target"

Condicionales (if/else)

Condicionales en Bash 
#!/bin/bash

# Verificar si eres root
if [ "$(whoami)" = "root" ]; then
    echo "Eres root. Puedes ejecutar este script."
else
    echo "❌ Necesitas ser root. Ejecuta con: sudo $0"
    exit 1
fi

# Verificar si un host está vivo
read -p "IP a verificar: " ip
if ping -c 1 -W 2 "$ip" &> /dev/null; then
    echo "$ip está ONLINE"
else
    echo "❌ $ip está OFFLINE o no responde"
fi

Bucles (for)

ping_sweep.sh — Tu primera herramienta 
#!/bin/bash
# Ping Sweep: descubrir hosts vivos en una red
# Uso: ./ping_sweep.sh 192.168.1

red=$1  # $1 = primer argumento que le pases al script

if [ -z "$red" ]; then
    echo "Uso: $0 <red>"
    echo "Ejemplo: $0 192.168.1"
    exit 1
fi

echo "🔍 Escaneando red $red.0/24..."
echo ""

for host in $(seq 1 254); do
    ping -c 1 -W 1 "$red.$host" &> /dev/null
    if [ $? -eq 0 ]; then
        echo "$red.$host está VIVO"
    fi
done

echo ""
echo "Escaneo completado."

¡Este script es tu primera herramienta de hacking! Hace un "ping sweep": envía un ping a cada IP de una red /24 (de .1 a .254) y te dice cuáles responden. Es una versión simplificada de lo que hace nmap -sn.

Ejecución: chmod +x ping_sweep.sh && ./ping_sweep.sh 192.168.1

$1 = el primer argumento que le pasas al script. $? = el código de salida del último comando (0 = éxito).
